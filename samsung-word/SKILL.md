# samsung-word: 표준 문서 작성 스킬

사내 표준 문서 작성 가이드(`references/guide_source.md`)를 그대로 구현한 워드
문서 생성 스킬. 폰트, 레벨별 기호·크기, 줄간격, 강조, 표, 페이지 번호까지
가이드의 세부 규칙을 자동으로 지켜주는 것이 핵심 가치이며, 사용자가 신경 써야
하는 것은 **내용을 개조식·수치 기반으로 정리하는 것**뿐이다.

## 언제, 왜 이 스킬을 쓰는가

이 가이드는 "형식을 매번 손으로 맞추는 시간을 없애고, 핵심만 빠르게
전달하는 문서를 만드는 것"이 목적이다. 그래서 이 스킬은 서식 계산(폰트,
간격, 기호, 페이지 번호 등)을 스크립트가 전담하고, Claude는 콘텐츠를
가이드가 요구하는 문체(개조식, 수치 기반, 레벨 구조)로 다듬는 데 집중한다.
문서 종류가 "일반 양식"인지 "전사 공유 양식"인지에 따라 목차·요약 페이지
유무, 여백이 달라지므로 작업 시작 전에 반드시 구분한다.

- **일반 양식**: 장애 보고, 가격 보고, 일정 보고, 출장 보고 등 단발성 문서
- **전사 공유 양식**: 현안회의, 전략회의, 경영계획, 정책서 등 전사·유관부서
  공유용 — 목차 페이지, 요약(목적·주장·결론) 페이지, 최소 여백이 자동 추가됨.
  목차는 Word 필드 코드가 아니라 실무 관행대로 **네모 박스를 페이지에 가운데
  배치**하고 그 안에 "목차" 제목과 1레벨 섹션 제목(번호 자동 부여)을 실제
  텍스트로 채운다 — 미리보기에서 바로 보이고, F9 업데이트가 필요 없다

사용자가 문서 종류를 밝히지 않았다면, 내용 성격(단발 보고 vs 전사 공유)으로
추정하되 애매하면 한 번 물어본다.

## 작업 순서

1. **내용 정리 (Claude가 직접)** — 사용자가 준 정보를 가이드 문체로 변환한다.
   - 서술형 문장 → 개조식 명사형/명사구로 축약 (종결어미 "-임/-함/-됨" 등도
     최대한 생략하고 명사구로 끝내는 것이 이상적)
   - "많이/크게/향상" 같은 형용사·부사 표현은 실제 수치가 있다면 반드시
     수치로 교체 (`제품 성능 향상 추진` → `제품 성능 30% 향상 추진`).
     수치가 없다면 사용자에게 확인하거나, 없다고 명시한다.
   - 내용을 1~5레벨 구조로 배치한다. 레벨을 건너뛰지 말고 상위→하위 순서를
     지킨다 (1레벨 아래 바로 3레벨로 가지 않기).
   - `□`(2레벨)는 **제목/소제목에만** 쓴다. 그 자체가 결론·판단·설명을 담은
     실제 서술 문장이라면 제목이 아니라 내용이므로 `-`(4레벨) 이하를 쓴다
     (예: "종합 의견"은 □ 제목, 그 아래 "단기 조정 국면이나 ... 유효"는 -).
   - 표로 표현할 수 있는 수치/비교 데이터는 표로 옮기고, 그래프나 이미지
     삽입은 지양한다.
   - 부연 설명이 필요하면 별도 문단이 아니라 `notes`(꺾임기호 ㄴ/ㄱ +
     Shift+Enter)로 처리한다.

2. **spec.json 작성** — `references/spec_schema.md`의 스키마에 맞춰 문서
   구조를 JSON으로 만든다. 예시가 그 파일에 있으니 그대로 따라 채운다.
   전사 공유 양식이면 `doc_type: "shared"`와 `summary`(목적/주장/결론)를
   채운다.

3. **문서 생성** — 스크립트를 실행해 실제 .docx를 만든다:
   ```bash
   python3 scripts/build_doc.py spec.json output.docx
   ```
   `python-docx`가 필요하다 (`pip install python-docx --break-system-packages`,
   설치 안 되어 있을 때만).

4. **결과 확인 및 전달** — 생성된 .docx를 열어 레벨 구조·표·페이지
   번호가 스펙대로 들어갔는지 확인한 뒤 사용자에게 전달한다. 강조가
   필요한 핵심 문구가 있다면, 필요 시 `scripts/build_doc.py`의
   `add_emphasis()` 함수를 참고해 밑줄+Bold를 직접 추가하는 보조 스크립트를
   짧게 작성해 적용한다 (spec.json 기본 흐름에는 강조 필드가 없음).

## 서식 규칙 요약 (스크립트가 자동 처리)

| 레벨 | 기호 | 폰트 크기 | 굵기 | 단락 앞간격 |
|---|---|---|---|---|
| 1 | 1, 2 … | 16pt | Bold | 14pt |
| 2 | □ | 14pt | Bold | 12pt |
| 3 | 1), 2) … | 14pt | - | 8pt |
| 4 | - | 14pt | - | 8pt |
| 5 | · | 12pt | - | 8pt |
| 주석 | ㄴ, ㄱ | 9pt | - | Shift+Enter |

들여쓰기는 **레벨 번호가 아니라 문서 트리에서 실제로 몇 단계 들어가 있는지
(depth)**로 정한다. 최상위 항목은 들여쓰기 없음, `children`으로 한 단계
내려갈 때마다 스페이스 1칸씩 늘어난다. 그래서 레벨을 건너뛰어도(예: 2레벨
밑에 3레벨 없이 바로 4레벨을 붙이는 경우) 절대 레벨 번호가 아니라 "부모의
자식"이라는 실제 위치 기준으로 딱 한 칸만 더 들어간다:
```
1. 장애 개요
 □ 발생 일시 및 영향
  - 복구 소요 42분        ← 3레벨을 건너뛰고 바로 4레벨을 붙여도 한 칸만 추가
   · 추가 내용
```
spec.json에서는 `children` 배열 안에 넣기만 하면 depth는 스크립트가 자동
계산한다 — level 번호와 depth를 따로 신경 쓸 필요 없다.

- 폰트: 바탕체 고정
- 줄간격: 1.08배, 뒤간격 기본 8pt (표 뒤 내용은 앞간격 8pt로 재정의됨)
- 강조: 밑줄 + Bold
- 페이지 번호: 하단 중앙, `1/전체페이지수` 형식 (Word 필드 코드로 자동 갱신)
- 텍스트박스·각주·미주 미사용 원칙을 지키기 위해, 부연 설명은 전부
  Shift+Enter 줄바꿈 + 꺾임기호로 처리한다 (별도 텍스트 상자를 만들지 않는다)

## 표 서식 규칙

- 표의 모든 셀(헤더 포함)은 예외 없이 **가운데 정렬**로 통일한다.
- 헤더(제목) 행은 밝은 회색(#D9D9D9) 배경 + 검정 굵은 글씨로 표시해서, 제목행과
  데이터행이 한눈에 구분되게 한다 (표 스크립트가 자동 처리, spec.json에서
  따로 지정할 필요 없음).

## 내용이 두 줄로 이어질 때

한 항목의 내용이 길어서 줄을 나눠 써야 할 때(주석이 아니라 같은 내용의
연속), **별도 문단(진짜 Enter)** 으로 이어 쓰고, 이어지는 줄 앞에는
기호(-, · 등) 없이 첫째 줄의 텍스트 시작 위치만큼(들여쓰기 depth칸 + 기호·공백
2칸) 스페이스만 넣는다 — depth가 1이면 3칸, depth가 2이면 4칸 식으로 항목의
깊이에 따라 자동 계산된다. spec.json에서는 해당 항목에 `wrap_lines`로 이어지는
줄을 배열로 넣으면 되고, 들여쓰기 칸 수와 문단 나누기는 스크립트(`add_continuation_line`)가
알아서 처리한다:
```json
{"level": 4, "text": "핵심 장비 이중화 적용 계획 수립 및 관련 부서 협의",
 "wrap_lines": ["4주 내 완료 목표로 추진"]}
```
꺾임기호(ㄴ/ㄱ)가 붙는 `notes`(부연 설명·출처 등 별도 성격의 내용)와는 다른
용도이니 혼동하지 않는다 — `wrap_lines`는 "같은 문장이 길어서 줄만 나뉜
것", `notes`는 "본문에 대한 주석/보충 설명"이다.

**처음엔 Shift+Enter(같은 문단 안 줄바꿈)로 구현했다가 별도 문단으로
바꾼 이유**: Shift+Enter 방식은 실제 Word와 미리보기 렌더러의 폰트 폭
계산이 미세하게 달라서, 앞부분 세그먼트가 예상보다 조금만 길어도 그 안에서
또 자동 줄바꿈이 일어나 들여쓰기 없는 셋째 줄이 생기는 문제가 있었다.
별도 문단으로 바꾸면 이 문제가 구조적으로 사라지고, 실제로 사용자가 Word에서
손으로 교정한 결과물도 이 방식(대시 없는 새 문단 + 들여쓰기 스페이스)을
쓰고 있었다. 그래서 분할 지점은 경계선에 딱 맞춰도 되고, 굳이 여유를 크게
둘 필요는 없다 — 문장이 자연스럽게 끊기는 곳(쉼표, 접속 표현 등)에서만
나누면 된다:
```json
{"level": 4, "text": "최고 725,000원(노무라 등 낙관적 전망), 최저 310,000원(BNK투자증권",
 "wrap_lines": ["등 보수적 전망)"]}
```

## 자주 쓰는 추가 요소

- `meta`: 제목 아래 우측 정렬로 날짜·작성 부서 한 줄 (예: `'24. 09. 10(월) 고객서비스팀`)
- 표의 `caption`/`source_note`: 표 위에 표 제목(가운데 정렬), 표 아래에 `※ 표 설명 or 출처 표시` 형식의 9pt 각주 자동 추가
- `end_marker`: 문서 맨 끝 `- 이 상 -` 표시 (우측 정렬). 기본으로 자동 추가되며, 필요 없으면 spec에서 `false`로 끈다
